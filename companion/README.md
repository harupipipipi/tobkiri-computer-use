# Tobkiri Cursor Studio

Computer Use の操作についてくる、編集できるキャラクターカーソル。
標準キャラクターはスカーフをつけた棒人間「Mochi」です。
48種類の連続アニメーション、手描きカーソル、透過PNGの連番アニメーションに対応します。
デスクトップ表示は Electron、アニメーションと編集画面は Canvas 2D です。
画像生成サービスや外部アカウントは不要です。

## 起動

Node.js **22.12以上**が必要です。リポジトリの `companion/` で実行します。

```sh
npm ci
npm start
```

初回は Electron をダウンロードします。インストール時のスクリプトを無効にしている
環境では `npm exec -- install-electron` を実行してください。
画面上部の「デスクトップに出す」で透明レイヤーを表示します。
「動き」タブで次のモードを選べます。

- **Computer Use の操作についていく**：Python / MCP の操作位置に表示。
- **自分のマウスについていく**：実マウスの位置を読み取り、その近くをキャラクターが走る。
  このモードは位置の読み取りのみです。グローバルなクリック・キー入力は監視しません。

`Ctrl+Shift+F8`（Macは `⌘+Shift+F8`）で表示を切り替えられます。
通常起動ではStudioを閉じると透明レイヤーも終了します。
MCP連動起動では常駐し、トレイから編集・表示切替・終了できます。
Windows / macOS 共通の構成です。今回のネイティブ描画試験はWindowsで実施しています。

## Computer Use と接続する

既存のOS別パッケージとCua Driverのセットアップが必要です。
Pythonでは、接続する `Computer` で有効にしてください。

```python
from tobkiri_computer_use import Computer

with Computer(companion=True) as computer:
    # windows() で確認した、操作を許可された対象のIDを指定する。
    window = computer.window(pid=PID, window_id=WINDOW_ID)
    state = window.observe()
    window.move(state.point(100, 100))
    window.locator("Apply").click()  # 対象アプリの要素を使う
```

要素名は対象アプリに合わせてください。通常は既存のComputer Useコードの
`Computer()` を `Computer(companion=True)` に変えるだけです。

MCPではサーバープロセスの環境変数を設定します。

```json
{
  "env": {
    "TOBKIRI_COMPANION": "1",
    "TOBKIRI_COMPANION_PORT": "47831"
  }
}
```

`TOBKIRI_COMPANION_PORT` は省略可能です。変更する場合はStudioの起動環境にも
同じ値を指定してください。環境変数の変更はMCPサーバーを再接続して反映します。
`Computer(companion=False)` は環境変数より優先して無効化します。
`computer.companion_status()` は送信状態と直近の到着応答を返します。
`renderer_ready` は描画側の到着応答であり、アプリ操作の成功を意味しません。
位置のある観測が必要なので、MCPの `tobkiri_observe` は標準の `screenshot: true` を使います。
画像を取得しない観測では、文字入力ができてもキャラの表示位置を特定できない場合があります。

### Codexに登録する（Windows）

WindowsパッケージとCua Driverのセットアップ、`companion` の `npm ci` を済ませ、
リポジトリのルートでPowerShellから実行します。

```powershell
$repoPath = (Resolve-Path .).Path
codex mcp add tobkiri-computer-use --env TOBKIRI_COMPANION=1 -- node "$repoPath\companion\scripts\mcp.cjs" "$repoPath\windows\.venv\Scripts\tobkiri-computer-use.exe" --surface compact --approval windows-dialog
codex mcp get tobkiri-computer-use
```

MCP接続時にキャラクター表示も自動起動します。Studioを開く必要はありません。
トレイの「キャラクターを編集」から見た目を変えられます。
既に開いているStudioがあれば、Computer Useモードへ切り替えて使います。
Codexのツール一覧に反映されない場合はMCPを再接続してください。

接続経路は **127.0.0.1 のUDPによる表示通知と到着応答** です。
Studioから入力命令を実行するAPIはありません。元の入力API、座標、Cuaの返却値、
物理入力の承認ルールは維持されます。表示が失敗しても入力を再送しません。
MCPの `tobkiri_act` とPythonのWindow APIは同じ経路です。
観測済みの対象を持つ低レベルCua呼び出しも対応します。
ブラウザのCDP専用API、未観測の対象、任意の他アプリの操作はこの通知の対象外です。

## できること

| 操作                                   | キャラクターの反応                                   |
| -------------------------------------- | ---------------------------------------------------- |
| 観測・移動                             | 名前付きセッションごとに出現し、操作位置へ歩く・走る |
| クリック / ダブルクリック / 右クリック | 手でボタンを押す、カーソルに波紋                     |
| type_text / set_value                  | キーボードを叩く                                     |
| press_key / hotkey                     | キーを押す                                           |
| スクロール                             | 両手で上 / 下に動かす（横方向も同じしぐさ）          |
| ドラッグ                               | 身体を傾けてひっぱる                                 |
| 拒否・例外                             | 困ったしぐさ。成功演出には変換しない                 |
| 対象が非表示・消失・リサイズ           | キャラクターを隠す。古い座標では再出現しない         |

ライブラリには上記のほか、ジャンプ、着地、つかむ、考える、待つ、手をふる、喜ぶ、
眠る、伸び、お辞儀、よじのぼる、浮く、踊る、覗く、座る、バランス、回転があります。
さらに、腰からひゅっと浮いて降りる・ひょいっと越える・柔らかい着地・前転・側転・
逆立ち・宙返り・ブレーキ・つま先歩き・横歩き・バウンド・キック・押す・懸垂・
ぶら下がり・あくび・肩すくめ・見回しを追加しました。
腰上げやバウンド、見回し、あくびなどは、操作を待つ間にもときどき再生します。
これらはライブラリからプレビューできます。移動・入力以外のしぐさが
勝手に実アプリを操作することはありません。

描画は `requestAnimationFrame` を使い、リフレッシュレートに合わせて更新します。
身体の追従とポーズ遷移は時間差で補間します。カーソル表示時の先端は通知された座標に
そのまま描き、身体だけを滑らかに追従させます。実測FPSはプレビューに表示します。
操作前にキャラが対象位置へ移動し、ポーズを取ってから入力します。
描画側が応答しない場合は最大60ms、応答した場合は最大1.26秒だけ待ちます。
タイムアウトしても入力を再送せず、既存の入力処理を一度だけ実行します。
`TOBKIRI_COMPANION_SYNC=0` で到着待ちを無効にできます。
入力アニメーションは試行を表し、一文字ごとの入力や成功を証明するものではありません。

## 自分のキャラクターを作る

設定画面上部の「表示」で **petだけ（カーソル非表示）** と **カーソル＋pet** を
切り替えます。標準はpetだけです。矢印・クリックの輪・カーソルの軌跡が消え、
キャラクターの動きと実際の入力位置は維持されます。色や自作カーソルは保持します。
JSONでは `displayMode: "pet"` / `"both"`。既存の設定にこの項目がなければpetだけになります。

「見た目」で色・サイズ・線幅・頭の大きさ・表情・スカーフを変更できます。
「カーソル」では32×32のドット絵を描くかPNGを取り込み、クリック位置を設定できます。
Shiftを押しながら描くと消しゴムになります。
ここで作るカーソルはキャラクターの透明レイヤーに表示されます。
OS全体のシステムカーソル設定は変更しません。

### オリジナルの連番画像

「動き」で置き換えたいしぐさを選び、横一列に並べた透過PNGを読み込みます。
1〜64フレーム、1〜60 FPS、PNGは2MB以下・8192×4096以内。
各フレームは同じ寸法で、横幅がフレーム数で割り切れる必要があります。
キャラクターの足元はフレームの下中央に揃えると位置が安定します。
未指定のしぐさは標準の棒人間にフォールバックします。

「書き出す」で画像も含む `.tobkiri.json` を保存できます。
ブラウザ版の設定はlocalStorage、デスクトップ版はElectronのuserData内の
`character.json` に保存します。この二つの設定は独立しており、書き出し・読み込みで移せます。
このリポジトリには [シンプルな赤い棒人間](examples/ember.tobkiri.json) のサンプルを含みます。

### 関節アニメーション

JSONの `clips` で、任意のしぐさを2〜24個のポーズに置き換えることもできます。
1ポーズは次の順序の10個の `[x, y]` 座標です。

```text
頭, 首, 腰, 左手, 右手, 左膝, 右膝, 左足, 右足, 目線のオフセット
```

足元が原点、上が負のYです。座標は-200〜200。
標準の1秒周期で各ポーズを順に補間し、最後から最初へループします。
`speed` で速さを変えられます。PNGと関節クリップの両方があればPNGを優先します。
形式・上限・全48個のしぐさIDは [config.js](src/config.js)、標準ポーズは
[engine.js](src/engine.js)、追加した動きのキーフレームは [motions.js](src/motions.js)
を参照してください。JSON内のコードは実行しません。

## 検証と制約

```sh
npm test
npx playwright install chromium
npm run test:ui
npm run test:desktop
```

実ウィンドウを30秒録画して描画間隔を計測するには、WindowsでFFmpegをPATHに置き、
`npm run record -- motion-check` を実行します。隔離した設定のStudioを一時的に開き、
そのウィンドウだけを録画します。出力は `test-results/recordings/` のMP4・WebM・JSON。
録画ファイルのフレーム数と、アプリの描画頻度は別の測定値です。
録画に伴うキャプチャ・エンコードでフレームが抜ける可能性もあるため、JSONには
録画前と録画中の `requestAnimationFrame` 間隔を別々に保存します。

実アプリの録画は `node tests/live-record.mjs bounds.json 30 live-check 47841`。
`bounds.json` は新しく観測した対象の物理画面座標 `{ "x": ..., "y": ..., "width": ..., "height": ... }` です。
操作用MCPは `--companion-port 47841` で起動します。録画用ポートを分けることで常駐表示と分離します。
録画スクリプト自身は入力しません。別のMCPクライアントから実際に観測・操作し、
画面と観測値の変化を確認してください。通常の表示はキャプチャから除外しますが、
この録画専用起動では `--recordable` によってキャラも映ります。
録画と実測値の詳細は [TESTING.md](TESTING.md) を参照してください。

`test:desktop` は隔離した設定を使って非表示のElectronウィンドウに描画し、
UDP受信・透明描画・非フォーカス・非表示・古いイベントの破棄・失効を検証します。
ユーザーのデスクトップには入力しません。画像はGit対象外の `test-results/` に保存します。

表示は非フォーカス・マウス透過のウィンドウです。ディスプレイごとに描画し、
Windowsの物理座標をElectronのDIPへ変換します。混在DPI・複数モニターの実機校正と
macOSでの最前面表示は未検証です。保護された画面や排他的フルスクリーンへの表示は
保証しません。有効なセッションではCua標準マーカーの代わりにキャラを表示します。

送信するのはセッションID、動作、画面位置、試行結果だけです。入力文字、キー名、
スクリーンショット、要素トークンは送信・保存しません。UDP到達は保証しないため、
静止時は約0.5秒の位置通知で復帰します。通常は3.5秒、長い入力の実行中は最大30秒で
通知の途絶えた表示を削除します。閉じた対象はhide通知で即座に非表示にします。

参考イメージはユーザー指定のMVとデスクトップ内を動く棒人間です。
同梱するキャラクター・イラスト・背景はコードで作成した独自のものです。
